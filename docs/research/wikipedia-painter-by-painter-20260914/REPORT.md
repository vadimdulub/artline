# Wikipedia artwork image research — 14 September 2026

**344 additional images were attached to existing artwork records in both the local and production catalogues**, covering 120 painters. Each counted image passed an exact-object source check, per-file rights assessment, visual review, database verification and a production HTTP checksum check. These figures belong to this painter-by-painter session; they exclude the preceding session’s 1,055 additions.

The research followed Wikipedia painter articles and their linked artwork lists, then checked the illustrated Commons files against the catalogue’s existing artwork identifiers. Wikipedia supplied discovery leads; a similar title alone did not establish that two records depicted the same physical artwork. The complete [painter checklist](CHECKLIST.md) and [image manifest](image-manifest.json) preserve the results and image-specific sources.

Popularity and regional groups overlap; their totals must not be added together. The active top-100 selection contains 99 painters because rank 24 is explicitly unselected. Regional membership follows the repository’s recorded priority affiliations, not a new nationality judgment. Counts describe artwork records, including distinct museum objects that can share a composition.

The source workflow reads article revisions through Wikipedia’s parsing API and stores retrieval receipts, response hashes, Commons file revisions and the artwork authority evidence. Large linked lists are processed in bounded metadata batches before any image is selected. There are 7 completed large-list supplements and 0 still outstanding; 29 painter records retain source errors or unresolved authority checks. A completed painter check does not mean every painting is available or reusable.[^1]

The Greek follow-up also checks authority-linked Commons categories for painters with eligible catalogue gaps: 27 painter checks covering 43 categories. This is bounded file metadata discovery, with at most three 100-member pages per category and three directly linked artwork subcategories. It does not download whole categories. The same physical-object, creator and rights gates apply to every resulting image candidate.[^6]

A separate Commons follow-up has checked 8 of 8 existing Russian creator authorities that have eligible gaps but no article in the selected Wikipedia languages. Its [plan](no-article-category-plan.json) follows only explicitly linked creator categories. Missing category authorities remain unresolved. A [Bashilov comparison](manual/bashilov-visual-review.json) confirms the same physical painting by its figures, details and crack patterns, while holding the cropped and grainier Commons reproduction for image quality.

A further 266 of 568 planned file checks examine Commons structured data for already-discovered, artist-scoped files whose rendered titles identify an artwork. The file's MediaInfo record must explicitly identify that same work through P6243 (digital representation of); depicted-subject claims and title similarity are insufficient. Matching records then pass the existing artwork, creator, date and rights checks. File entity revisions and API receipts are retained in `structured-file-entities/` and individual outcomes in `structured-file-checks/`.[^7]

The remaining exact-authority follow-up has completed 126 of 126 planned existing, eligible painting records with documented museum or selection evidence. Their current P18 image claims are discovery leads; independent Commons object identity, creator agreement, dates and rights are still required. Multiple primary-image claims and different physical versions remain unresolved. This supplements the completed painter-article pass without downloading whole collections.

The Greek museum-language pass checked 49 actual Commons source links, producing 6 exact object matches, including alternatives already found elsewhere. The museum's own language-switch links connect the Greek source pages to existing English catalogue object URLs; current accession and creator evidence are checked separately. These results are preserved in `greek-museum-language-checks/`. The [translated-title review](manual/greek-translated-comparisons-finished.json) adds direct comparisons with primary museum reproductions. For example, the comparison accepts Maleas's Egyptian landscape and Lytras's *Funeral Flowers*, but rejects a finished Queen Amalia portrait for a record describing a small preparatory study, and rejects a different Helsingør harbour scene. Positive research decisions are counted as additions only after database and delivery verification.

While the separate authority API was unavailable, 36 remaining linked-article items received an independent Wikipedia/Commons prefetch, with 31 successfully retrieved pages. Exact matches could use valid cached authority evidence; missing authorities remained pending. Overall Wikipedia totals above are deduplicated by page URL and revision across painter, linked-article and prefetch records.

Exact matches require the same existing artwork authority, a complete accession with the same institution, or the exact museum object URL. Creator and available date evidence are checked independently. Unknown dates, conflicting attributions, ambiguous objects and the existing Doxaras date discrepancy remain in review. Museum holdings are not treated as evidence of current display.

Thirteen Greek creator identities were reconciled for source research only, using recorded museum references and Wikipedia/Wikidata evidence. The [research authority register](research-creator-authorities.json) preserves the basis and conflicting biographical dates. These mappings did not merge artists or change database names, dates or biographies. They support discovery; each artwork and its reproduction still pass separate identity and rights checks.

A further research-only mapping connects the existing Mikhail Matiushin record to Mikhail Matyushin through the exact MoMA artist identifier 3834 and corroborating life dates. The existing separate artist records were not merged.

One Ivanov image was withdrawn after direct comparison exposed an incorrect Commons museum URL: the file depicted a church landscape, while museum accession Р-5643 depicts the coastal fortress at Sudak. The withdrawal removed this session's media association in both catalogues and its own distributed asset; original inputs, private derivatives and transaction evidence remain in [the withdrawal record](withdrawals/ad9bb5fa-e4e6-473f-9a44-8c9549fde899/result.json). It is excluded from the delivered count. Explicit file-date discrepancies now receive an additional review before image approval. [Source-date reviews](source-date-reviews.json) distinguish incorrect object matches from photograph dates and documented alternative historical datings, without modifying catalogue dates.

Further primary comparisons resolved two Russian date holds. The Hermitage's published catalogue, entry 371 (printed pages 272–273), identifies and reproduces Pimen Orlov’s signed 1835 portrait, accession ЭРЖ-191; the [comparison](manual/orlov-erzh191-visual-date-review.json) distinguishes its incorrect Commons date from the unchanged catalogue date. A different Commons reproduction of Ostroukhov’s *Golden Autumn* agrees with the Tretyakov Gallery’s 1886 dating and matches its complete composition in a [direct comparison](manual/ostroukhov-1467-alternative-review.json). Positive image decisions enter the totals only after attachment and delivery verification.[^8][^9]

The date discrepancy check also recognizes Commons' explicit “before” and “after” template forms as bounds, not single creation years. That resolves false discrepancies for Tsokos and Morisot while retaining concrete conflicting dates. A 1968 postage stamp depicting Avilov’s 1943 painting is held as a separate reproduced object; a stamp exemption is not treated as permission to substitute the stamp for the painting.[^10]

Commons licences are assessed on the individual file page. Creative Commons files retain the photographer or image author, source and licence link, together with a notice of proportional resizing and JPEG compression. The raw file description is checked because an Artwork template can hide photographer fields from rendered metadata. The Stavrakis photograph’s author was corroborated against its explicit original own-work upload, preserved in [the credit review](credit-review/stavrakis-uploader.json). Files with unresolved reproduction authorship are held. Commons itself directs reusers to inspect each file’s licensing and attribution requirements.[^2][^3]

Only selected reproductions were downloaded. Images retain the downloaded source frame and are compressed to at most 100,000 bytes; no AI reconstruction, invented detail or new crop was introduced. Visual review checks legibility, coherence, framing and glare. The Surikov reproduction with substantial glare was retained as research evidence and was not attached. Archived input reproductions and database backups are outside Documents; their locations and checksums are recorded in the session evidence. A photograph’s licence is not automatically treated as permission for separate underlying artwork rights. Recent-creator and country-specific cases remain individual review items.[^4]

Two Titian sources were rejected because they clipped the upper composition of *Sacred and Profane Love*. A third source includes the full composition and visible canvas boundary; its exact Commons structured identity and museum accession are preserved in [the replacement review](manual/titian-quality-replacement-review.json). Rejected derivatives remain private. Primary comparisons also record differences between reproductions, such as warmer colour balance or slightly different peripheral coverage; the files are not silently recoloured, reconstructed or presented as museum-calibrated masters.

Separate public-domain source alternatives resolved the image-credit holds for Monet’s *The Museum at Le Havre* and Delacroix’s *Ugolino and His Sons*. Their [Monet](credit-review/monet-le-havre-alternative-resolved.json) and [Delacroix](credit-review/delacroix-ugolino-alternative-resolved.json) reviews preserve the original unresolved CC claims and the accepted file identities. Delacroix’s identity bridge uses the exact existing artwork image claim, explicit reciprocal version links and matching object details; its museum corroboration came from indexed primary-page text because direct museum URLs returned 404. Neither alternative licenses the earlier unresolved photograph.

A monochrome Mondrian file explicitly labelled “first state” remains private. The [object follow-up](manual/mondrian-94-3-primary.json) also records a possible conflation: the selected file identifies *Tableau no. II*, catalogue number B121.154, while the official Beyeler record associates the existing accession 94.3 with *Tableau No. I*, B113.153. The artwork authority/accession association needs editorial reconciliation; this image task does not correct it or substitute a different painting.

Wikimedia returned HTTP 429 responses during image delivery. The queue honored the recorded Retry-After and longer cooldowns, with request spacing persisted across batch boundaries. The second response explicitly recommended standard thumbnails; the subsequent plan uses API-returned 960-pixel thumbnails, preserving the original file’s identity checksum and the downloaded input’s own checksum. This follows the provider’s documented workflow and keeps the source cooldown in force.[^5] Source refusals, transport failures and unapplied candidates remain explicit in [the follow-up register](follow-up-candidates.json), `provider-pause-history/` and `provider-pauses/`. Source limits do not justify bypassing a refusal or claiming an image was added when it was only discovered.

Wikidata separately returned API overload (`maxlag`) responses. Those authority requests pause for the recorded cooldown while valid cached evidence and independent source work remain available. The client retains `maxlag=5`; archived error bodies, receipt hashes and retries are preserved in `metadata-overload-history/`. Missing or interrupted source responses are not interpreted as an absence of artworks.

Every application used a frozen before-state and checked the current local and production record before attaching media. The transactions changed only media associations and their audit fields. No artwork dates, titles, creator links, holdings or editorial status were changed by this session. All immediately verified batches confirmed metadata preservation. The final read-only audit recorded 2 later metadata differences; details, if any, are in [the verification summary](summary.json). Later differences are reported without attributing their cause or overwriting them. No commit, deployment, artwork publication or new artwork ingestion was performed.
