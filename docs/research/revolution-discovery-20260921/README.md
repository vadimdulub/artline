# Revolution discovery, artwork navigation and book review — 21 September 2026

Applied to the local research catalogue and application. No deployment, publication, commit or museum outreach. The 1970 artwork creation cutoff remains in force.

## Interaction changes

- “With pictures” is inside each creator’s **Artworks by year** list in the Painters/Art screen. Filtering changes the server-owned totals, year groups, pages and previous/next sequence together.
- All always requires artworks with renderable attached pictures. There is no main-screen image checkbox.
- Previous/next arrows move through **individual entries** in the current filtered layer, including across page boundaries and directly linked records. They stop at sequence boundaries. Browse also has previous/next pages; responses stay bounded.
- Enlarged artwork mode retains the open dialog while navigating. Each new image starts fitted, with 44px navigation targets on phones.
- Highlights is enabled initially and after Reset view; users can switch it off. Clear filters clears Highlights. The shared switch removes stale book/event highlight overrides. “Book highlights” replaces the fixed “Top 100 books” label.
- French and Russian Revolution periods use recorded country associations plus explicit related records. Three selected surrounding events in each are labelled **Context**. These are editorial associations, not claims of influence. User country/search/native filters still intersect this focus. Changing years retains it; removing the historical period or Zoom out clears it.
- Earlier work is retained: all 30 starting points, the main group centered, timeline-width interval zoom, Zoom out, multi-country discovery and artwork “View” actions.

## Query plans and remaining scale work

Captured 36 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` plans in `query-plans/`; timings are summarized in `query-plan-summary.json`. These use the real local catalogue of **297,559 artworks, 23,442 artists and 101,223 media records**.

The final audit found an important query-plan regression: applying the mandatory image predicate twice caused broad All requests with Highlights off to exceed the ten-second API timeout. All now applies that predicate once; both `artwork_image_only=true` and `false` preserve the mandatory rule. The same endpoint requests subsequently completed in 0.44 seconds for 1910–1930, 1.41 seconds for 1700–1970 and 1.82 seconds for the full range. Captured broad artwork plans took approximately 1.76–3.27 seconds; focused Russian and French artwork plans took 135 ms and 725 ms, respectively. Timings vary with cache and concurrent activity.

The native creator query still starts with indexed creator/artwork links. Metadata enrichment is limited to returned page IDs. No full collection is transferred to the browser. Aggregates and neighbor lookup still evaluate the matching relation, so these observations are **not** evidence of ten-million-artwork capacity. Representative load testing, aggregate projections and their invalidation remain explicit future backend work; no large test fixture or bulk ingestion was authorized for this local task.
